# 11. 落地路线

> [← 10-platform](10-platform.md)　|　[附录：ADR](appendix-adr.md)

## 五阶段

| 阶段 | 目标 | 交付物 |
|---|---|---|
| **一·最小闭环** | 一个真实 Java 仓库跑通 | 拉代码+编译+轻量提取API资产表+CodeQL扫描+check表+AI从API出发验证+result表+前端展示 |
| **二·稳定性** | 可重试可复用可隔离 | 状态机+重试+幂等+CodeQL DB缓存+构建隔离+**合并验证(ADR-21)** |
| **三·信息融合** | 深度信息+版本对比 | 深度补充层+完整调用链+check表全覆盖+**增量扫描(ADR-22)**+版本对比 |
| **四·AI增强** | AI分层+反馈闭环 | **AI分层过滤(ADR-23)**+**自动优化反馈闭环(ADR-24)**+Benchmark+效果追踪 |
| **五·平台增强** | 规模化运营 | 服务重要度+跨仓分析+CI/CD阻断+规则运营平台 |

## 优化机制落地节奏

| 优化 | ADR | 阶段 | 理由 |
|---|---|---|---|
| 合并验证 | ADR-21 | 二 | 成本低收益直接 |
| 增量扫描 | ADR-22 | 三 | 依赖完整调用链做反向索引 |
| AI分层过滤 | ADR-23 | 四 | 需样本量验证小模型准确率 |
| 反馈闭环 | ADR-24 | 四 | 需 Benchmark 做效果追踪 |

## 阶段一启动前置

1. 本架构文档定稿
2. 数据库 schema 迁移脚本设计（七张核心表）
3. sail.yaml 配置 schema 确认
4. CodeQL 规则包选择（1-2 条，如 SQL注入+硬编码凭证）
5. 测试用 Java 仓库准备（含已知漏洞的 Spring Boot 项目）

## 阶段一不做

多Agent / 自动修复 / 跨仓 / 复杂权限 / Istio / 大量规则 / AI批量分层 / NO_BUILD降级 / 增量扫描 / 自由代码问答

## 质量保障

| 测试类型 | 内容 | 阶段 |
|---|---|---|
| Java 提取器测试库 | Spring MVC/WebFlux/JAX-RS 等小型仓库+期望结果 | 三 |
| CodeQL 规则回归 | 真漏洞+安全实现+边界样例 | 一 |
| CodeQL DB 构建回归 | 同仓库新版本构建成功率回归 | 二 |
| AI Benchmark | 人工标注集，评准确率/漏判率/成本 | 四 |
